# Known limitations and release gate

The build environment is Debian Linux. The Windows publish and portable tests succeeded, but **the app has not run on native Windows**. It must not be represented as stable, universally compatible, production-ready, or feature-complete. See the parity audit and actual test log.

- Native tray, hook delivery/suppression, WPF rendering, focus restoration, privacy guard, real text insertion, clipboard file formats, startup registration, and clean exit need Windows validation.
- Notepad, Edge/Chrome/Firefox, Word, VS Code, Discord and other messaging apps have not been tested. Word and some Electron/browser editors may not expose the required writable accessibility metadata or a usable TextPattern selection. These fail closed. Elevated apps, secure desktops, protected fields, remote sessions and browser virtualized text editors may reject input or be unsupported. Comet does not elevate, use uiAccess, bypass UIPI, or cross a security desktop.
- Password protection relies on provider-reported metadata plus process exclusions. Unknown fields are disabled. A custom application that falsely reports a password as a normal editable field cannot be reliably identified. Focus notifications and polling have a finite race window; exact-range verification rechecks password state before any deletion.
- Autocomplete uses tracked ASCII candidates, not a TSF text service or durable application edit transaction. It cannot atomically lock a remote caret. Programmatic edits/focus/caret changes after final verification remain a small race. No automatic retry follows partial injection.
- Selection/preceding-text verification requires TextPattern. ValuePattern-only controls may show suggestions but cancel replacement; use picker Copy. The verification reads a bounded range, never whole documents or full field values. A hung provider pauses further verification until it returns or Comet restarts.
- IMEs are disabled while open when detected. Dead keys, multi-character translations, AltGr/composition and complex keyboard layouts are conservatively cancelled. Physical layout behavior is untested. Remote automation input is ignored by default; `--test-input` is solely for opt-in synthetic tests and should not be used daily.
- Holding modifiers can cancel insertion. A shifted closing trigger has a short modifier-release wait. Enter/Tab/arrow suppression, autorepeat and rapid typing still need native stress testing.
- Win32 caret placement falls back to the mouse when unavailable. Mixed-DPI monitor positioning, offscreen recovery, touch/pen caret movement and accessibility caret-only editors need validation.
- Snippet newlines become Enter keys. In chat applications this may send messages. Date/time variables use .NET formats and Windows locale at insertion time; they approximate the source token names, not verified macOS formatting. Unknown tokens stay literal.
- Metadata is independently licensed and is not an exact copy of Rocket's 5,225-row base catalog. The emoji font and Windows version determine visual support. Mixed skin-tone sequences are indexed but not offered through independent per-person tone controls. English metadata, limited fuzzy ranking and a 400-result picker limit are intentional current bounds.
- GIF support is local-file import, name search, animation and attachment clipboard copy. No online GIF provider, bundled reaction artwork, GIF shortcode expansion, or automatic rich GIF insertion is included. Exports contain file paths, not portable GIF assets. Removed GIF entries retain managed files for clipboard/export safety.
- No website-specific browser exclusions, full glyph/ASCII catalog, French UI, arbitrary hotkey recorder, dedicated statistics dashboard, auto-updater, signed executable, signed MSI or machine-wide installation is supplied.
- No Explorer-restart tray recovery, session shutdown soak testing, or long-duration memory/CPU measurements have been completed. Performance figures in TEST-RESULTS are from the portable Linux test process, not Windows background-app measurements.
- The optional installer/uninstaller scripts have been reviewed but not executed on Windows. Startup paths depend on the application's location when Settings is saved. Keep all self-contained runtime files alongside Comet.exe; the EXE alone is insufficient.

Before a production release: run the supplied Windows harness, perform the full real-application checklist, fix native failures, measure hook latency/idle resources, add Explorer/session recovery as needed, soak-test, and obtain signing if distributing broadly.
