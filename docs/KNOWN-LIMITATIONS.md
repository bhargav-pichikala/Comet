# Comet 0.2 — known limitations

The build environment is Debian Linux. The portable suite passed, but **no native Windows execution is available**. The reported 0.1 one-use failure's precise native root cause is unverified. Code changes address confirmed parser/ranking defects, session races and the shared-UI-thread hook risk; they are not evidence of a successful native 100-cycle run. See BUG-INVESTIGATION-0.2.md.

- No native tray, hook, focus, caret/provider, keyboard-layout, clipboard, startup, shutdown, screenshot-export, installer or Desktop-copy pass is claimed. The bundled Windows runner was published but not run. Its 100 synthetic cycles target a separate WPF text box; even a successful run would not prove physical input or all other editors.
- Notepad, Chrome/Edge/Firefox, Word, VS Code, Discord, ChatGPT inputs and Windows Search are all NOT VERIFIED. Providers may lack writable metadata, TextPattern verification or caret geometry. Such fields fail closed. Elevated apps, secure desktops, protected/remote fields and security boundaries are never bypassed.
- Password protection depends on provider metadata. Unknown/stale fields are disabled; misreported custom password controls cannot be perfectly identified. Only the bounded candidate range is read for verification, not entire field values/documents. Settings/snippets remain local plaintext.
- The input pump is isolated from WPF work, but native hook timing and silent-hook-removal behavior need Windows stress tests. Diagnostics expose counts/status, not typed characters. Provider calls can hang; guard/caret snapshots expire. A hung verification pauses further replacements until that call returns or the app restarts, rather than bypassing verification.
- Win32 caret, UIA collapsed selection geometry and MSAA OBJID_CARET are used. If no fresh, reliable caret is available, no inline popup is shown and invisible suggestions do not intercept Enter. Use the explicit picker/Copy. Blank fields, end-of-document ranges, provider quirks, RTL layout, mixed DPI and monitor changes need native validation. No mouse-position or whole-control rectangle fallback is used.
- UIA verification and SendInput are not an atomic remote edit. A narrow race after final verification remains. Changed typing/focus/modifiers cancels instead of retrying. Partial injection is reported without replay. TextPattern-only constraints may leave some editable fields unsupported.
- IMEs are disabled while open when detected. Dead keys/multi-character translations and AltGr/complex composition are conservatively cancelled. Holding modifiers can cancel insertion. A shifted closing trigger has a short release wait.
- Newlines in snippets become Enter key events and can send a chat message. Use multiline editors. Date/time formats approximate macOS token names using Windows culture; unknown tokens stay literal. Unicode is preserved, but font/app rendering varies.
- The popup adapts the supplied screenshot with Windows Segoe UI and original WPF styling. No proprietary fonts/art are copied. Pixel-perfect parity and live visual placement are not claimed. Browser design HTML is not a WPF screenshot; `--popup-preview` can export the real WPF visual on Windows, but was not executed here.
- Full picker results are capped at 400; metadata differs from Rocket's catalog. Mixed skin-tone sequences are indexed without independent per-person tone controls. English only. Existing normal windows keep their theme until reopened.
- GIFs are authorized local files with animation/name search/attachment clipboard copying. No online provider, bundled reaction pack, GIF shortcode expansion or automatic rich GIF insertion. Exported settings contain machine-local GIF paths. Removing entries retains managed files for clipboard/export safety.
- No per-website browser exceptions, full ASCII/glyph catalog, arbitrary hotkey recorder, French UI, statistics dashboard, updater, code signing or MSI. Explorer/session recovery and long-duration memory/CPU soak tests remain pending.
- Existing 0.1 ZIPs are preserved. Extract 0.2 into a new folder; quit the old process first. `Install-To-Desktop.ps1` backs up the old Desktop folder before copying, but this helper and optional installer scripts have not run on Windows here. Startup points to the path used when Settings was saved; update it after moving the app. Keep every runtime file alongside the EXE.

Release gate: run the Windows 100-cycle runner, physical Notepad/other-editor checks, live caret/DPI/focus inspection, privacy/cancellation cases and extended soak. Record actual failures/results before any production-ready or native-fix-complete claim.
